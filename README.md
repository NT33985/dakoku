# 打刻フォト — iPhone用PWA

始業・終業の打刻機の写真を **iPhone内だけ** で保存・確認する個人用アプリです。通知・ログイン・外部への画像送信はありません。

## アプリに入っているもの

- 1日につき始業・終業の各1枚。写真を撮る → プレビュー → 保存
- 当日に限り撮り直し可能。上書き前に確認
- 自動JPEG圧縮（長辺最大1800px、JPEG画質85%）
- 今日の撮影状況と月間カレンダーを1画面表示
- 土日・日本の祝日を休日として表示、有休・休日出勤などは日付タップから手動変更
- 過去の写真は閲覧・拡大・個別出力のみ
- 月単位ZIP出力（写真、CSV、復元用JSON）
- ZIPからの復元。既にある写真・休日設定は上書きしない
- 保存枚数と写真容量の表示
- **過去の月のみ**、写真と手動休日設定を確認後に削除。自動削除はしない
- オフライン撮影・保存・閲覧（最初にオンラインで読み込み、PWA用ファイルの保存が完了したあと）

## GitHub Pagesへの導入手順

GitHub のウェブサイトで以下を行います。

1. 新しいリポジトリを作成します。例：`dakoku-photo`。公開設定は **Public** にします（GitHub Pagesの利用要件はプラン・公開設定で変わります）。
2. このZIPをPCで解凍し、**`dakoku-photo-pwa` フォルダの中身**をリポジトリの一番上（ルート）にアップロードします。フォルダ自体を一段深く配置しないでください。
3. `index.html` / `app.js` / `styles.css` / `manifest.webmanifest` / `sw.js` / `icons/` がルートに存在することを確認します。
4. リポジトリの **Settings → Pages** で **Deploy from a branch** を選び、Branchを `main`、Folderを `/(root)` にして **Save**。
5. Pagesの公開URL（例：`https://ユーザー名.github.io/dakoku-photo/`）にアクセスし、画面が表示されることを確認します。初回のみインターネットが必要です。
6. iPhoneの **Safari** で公開URLを開き、共有メニューから **ホーム画面に追加**。表示されたら **Webアプリとして開く** を有効にして追加します。
7. ホーム画面にできた「打刻フォト」から起動し、カメラの利用を許可して撮影します。

> **重要**：写真はGitHubに保存されません。GitHubへ公開するのはアプリのプログラムのみです。写真が写り込んだファイルを誤ってアップロードしないでください。GitHubのREADMEやコミットに個人情報を入れないでください。

## 使い方

- 朝：会社の打刻機で打刻 → 「始業 写真を撮る」 → 写真確認 → 保存。
- 夕：同様に「終業 写真を撮る」から保存。
- 写真を開く：保存済みの始業/終業、またはカレンダーの日付をタップ。写真はタップで拡大できます。
- 休日の編集：カレンダーの日付 → 「休日にする」または「出勤日にする」。必要なら「自動判定に戻す」。
- 月の出力：右上の歯車 → 月を選択 → 「この月をZIPで出力」。共有シートが開いた場合は「ファイルに保存」→「このiPhone内」を指定してください。
- 写真単体の出力：写真を拡大 → 「この写真を出力する」。
- 復元：右上の歯車 → 「バックアップZIPを読み込む」 → 先に書き出したZIPを指定。重複する写真はスキップし、古い写真を勝手に置き換えません。
- 削除：右上の歯車 → **過去の月**を指定 → 削除ボタン → 指定された月を入力して最終確認。復元できるよう事前にZIPを出力してください。

## 端末内保存と安全上の注意

1. 写真はSafari / ホーム画面Webアプリの **IndexedDB** に保存され、iPhone標準の「写真」アプリには自動保存しません。写真をサーバーに送信するコードはありません。
2. 端末のサイトデータ削除、アプリ削除、容量不足、機種変更等で写真が失われる可能性があります。**毎月ZIP出力し、iPhoneの「ファイル」アプリなどに別途保管してください。** バックアップを出力しない限り、復旧できないことがあります。
3. ホーム画面版とSafari画面版で保存領域が分かれる場合があります。普段は同じホーム画面アイコンから使用してください。複数のアイコンや別URLでデータが共有される保証はありません。
4. 出力ZIPの写真やCSVは暗号化されません。会社の規則に従い、端末外に転送・共有しないようにしてください。
5. 日時は写真選択が完了したときの端末時計から記録する **撮影操作の記録時刻** であり、会社の打刻システムが正式に記録した時刻ではありません。写真と時刻は打刻の法的証明や会社の正式な出退勤記録に代わるものではありません。
6. `capture="environment"` で背面カメラを要求していますが、iOSの画面・バージョンによっては撮影方法の選択肢が出る場合があります。
7. 日本の祝日は規則から算出しています。会社の独自休日・法律の改正や臨時祝日があれば手動で変更してください。
8. ブラウザの保存領域には空き容量の制約があります。保存エラーが出たらその写真は保存されず、前の写真は保持されます。容量に余裕がない場合は出力・整理を行ってください。

## ZIP仕様（アプリ自身で出力したZIPを復元してください）

```text
打刻フォト_2026-10.zip
├── manifest.json           # 復元用データ
├── 打刻記録一覧.csv          # Excelで開けるUTF-8 BOM付きCSV
├── 2026-10-01/
│   ├── 始業.jpg
│   └── 終業.jpg
└── 2026-10-02/
    └── 始業.jpg
```

外部JSライブラリなしでZIPを生成します。ZIP内の写真は既にJPEG圧縮済みのため、ZIPでは無圧縮（STORE）として格納します。復元時はCRC-32・ファイル形式・記録日時を検証します。他のソフトで作った圧縮ZIPは読めないことがあります。

## 更新方法

1. 変更したアプリファイルを同じGitHubリポジトリにアップロードして置き換えます。**保存写真をZIPとしてGitHubへアップロードしないこと**。
2. オフライン用プログラムを変更した際は `sw.js` の `CACHE_NAME` を `dakoku-photo-shell-v2` のように変更します。新しいアプリが配布されても保存写真のデータベースは削除しません。
3. iPhoneでアプリを再起動し、必要ならオンラインで再読み込みします。アップデート前に念のためZIPバックアップを出力してください。

## 配布ファイル

`index.html`（画面）, `styles.css`（デザイン）, `app.js`（写真・記録・ZIP処理）, `sw.js`（オフライン用キャッシュ）, `manifest.webmanifest`（PWA設定）, `icons/`（ホーム画面用アイコン）

動作想定：iOS Safari + GitHub PagesのHTTPS。実機iPhoneでの動作確認は利用者側でお願いします。
